# 코드 리뷰 수정 기록 (2026-09-06)

## 변경 사항

- 토크나이저 corpus는 샤드별로 문서/문자 예산을 나누고, 각 샤드 전체를 읽어 고정 seed의 난수 우선순위로 표본을 유지한다. 전체 문서의 균일 표본이 아니라 샤드별 동일 예산의 층화 표본이다. 문자 예산 경계 문서는 일부만 포함될 수 있으며, 샤드별 유효 문서 수와 채택량을 체크포인트에 저장한다.
- corpus를 UTF-8 기준 최대 4,096바이트로 분할한다. SentencePiece에도 같은 제한을 명시하고, 학습 전에 초과 줄이 없는지 검사한다.
- corpus와 토큰화 체크포인트는 버전 2다. 입력과 토크나이저의 SHA-256, 출력 경로, 샘플 한도 등을 비교한다. 설정이 다른 완료 결과나 버전 1 기록은 자동 재사용하지 않는다.
- 토큰화의 완료 샤드는 `.bin/.idx` 해시가 일치할 때만 건너뛴다. 손상된 샤드는 다시 처리한다. 현재 입력에 없는 이전 출력 샤드와 중복 출력 이름은 거부한다.
- 전처리의 `work-dir/pipeline_state/`에 단계별 계약과 datatrove 완료 로그를 보존한다. 입력 목록·크기·수정 시각, tasks, 코드 해시가 달라지면 재개를 거부한다. workers는 모든 dedup 단계에 전달하며 단계의 tasks 이하로 제한한다.
- JSONL 읽기는 UTF-8을 명시하고 손상을 예외로 처리한다. 각 단계 출력의 gzip/JSON/텍스트와 문서 존재를 전체 검사한 다음에만 이전 중간 결과를 정리한다. 정리 여부도 기록하므로 정리 후 재실행이 가능하다.
- 샤드 자동 재시도는 작업 디렉터리를 지우지 않는다. 완료된 Parquet 분할과 datatrove 작업을 재사용하며 로그를 이어 쓴다. 최종 실패는 종료 코드 1이다.
- 재개 스크립트는 저장된 샤드를 이름 충돌 없이 별도 폴더에 합친다. 가능하면 하드링크를 사용하며 저장 원본은 보존한다.
- DataLoader는 전용 generator에 seed를 적용한다. `drop_last=False`가 기본이며 고정 크기 학습 배치가 필요할 때 `True`를 명시한다. 학습 중간부터 정확히 이어가는 기능은 학습 루프의 sampler/RNG 체크포인트가 별도로 필요하다.
- 배치 파일의 분할 스크립트 경로와 종료 코드를 수정했다. GPT-2 예제의 마지막 `NameError`를 제거하고 import 시 모델을 내려받거나 실행하지 않도록 했다.

## 호환성과 검증 범위

기존 corpus, 토크나이저 모델, 토큰 데이터는 이번 코드 수정 과정에서 재생성하거나 변경하지 않았다. 과거 모델의 긴 문서 제외 문제는 코드 변경만으로 소급 복구되지 않는다.

이전 체크포인트를 묵시적으로 승계하지 않는다. corpus 재생성에는 `--rebuild-corpus`, 토큰 결과 교체에는 `--overwrite`가 필요하다. 다른 실험은 출력뿐 아니라 체크포인트 경로도 분리해야 한다. 전처리에서 계약이 다르거나 완료 기록 없는 기존 결과가 있으면 새 work/output 경로가 필요하다.

해시 검사와 출력 전체 검증은 대용량 파일을 추가로 읽는다. 중간 결과와 분할 입력을 삭제하면 디스크는 절약되지만 기록 없이 임의 삭제한 파일의 복구까지 보장하지 않는다.

회귀 테스트:

```powershell
python -X utf8 -m unittest discover -s tests -v
```

테스트는 프로젝트 안에 독립된 작은 임시 입력을 생성하며 기존 `data/`를 사용하지 않는다. 실제 datatrove의 작업 실패/재개, exact/minhash, 작은 SentencePiece 학습을 포함한다. Windows의 제한된 실행 환경에서는 datatrove 프로세스 간 파이프 권한이 필요하다. 대용량 corpus 전체 재처리와 GPU 학습은 검증 범위에 포함하지 않았다.
